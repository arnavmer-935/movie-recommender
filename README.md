# Movie Recommender

A content-based movie recommendation system built with Python, scikit-learn, and Streamlit. Given a movie title, it returns 5 similar movies based on overview text, genre, keywords, cast, and director, and displays them alongside live poster art from the TMDB API.

This project was originally prototyped as a single Colab notebook and later refactored into a modular Python project, with a focus on separating data loading, cleaning, model training, and presentation into distinct, single-purpose files.

## Tech Stack

- **pandas** — data loading, merging, and cleaning
- **scikit-learn** — `CountVectorizer` and cosine similarity for the recommendation model
- **Streamlit** — web app front end
- **requests** — TMDB API calls for poster images
- **python-dotenv** — loads the TMDB API key from `.env`
- **pickle** — persists the trained model to disk

## Getting Started

1. Download `tmdb_5000_movies.csv` and `tmdb_5000_credits.csv` from the [TMDB 5000 Movie Dataset on Kaggle](https://www.kaggle.com/datasets/tmdb/tmdb-movie-metadata) and place both in `data/`.
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Add a TMDB API key to a `.env` file in the project root:
   ```
   API_KEY=your_tmdb_api_key_here
   ```
4. Train the model:
   ```bash
   cd src
   python train.py
   ```
5. Run the app:
   ```bash
   streamlit run app.py
   ```

The trained model lives in `models/`, generated by step 4. `app.py` only reads from `models/` — it never trains anything itself, so re-run `train.py` any time the source data or cleaning logic changes.

## How It Works

The recommender is content-based; it has no notion of user ratings or collaborative filtering. For each movie, a single `tags` string is built by combining its overview, genres, keywords, top 3 billed cast members, and director. `CountVectorizer` turns these tag strings into vectors, and cosine similarity between vectors becomes the similarity score between movies. Recommending a title is just returning its 5 nearest neighbors in that similarity space.

```
recommend("The Dark Knight Rises", movies, similarity)
→ 5 nearest titles by cosine similarity over tag vectors
```

Poster images are fetched live from TMDB by `movie_id` at render time — they aren't part of the trained model and require network access to display.

## Design Decisions

- **Tags are built from five fields, not just overview text.** Overview-only similarity tended to group movies by writing style more than content; adding genre/keywords/cast/director tags nudges recommendations toward thematically or creatively related movies.
- **Cast is capped at the top 3 billed actors.** Including the full cast list let minor/background actors dominate the similarity signal for ensemble films; billing order is used as a proxy for relevance.
- **Multi-word names and terms are space-stripped before vectorization** (e.g. `"Sam Worthington"` → `"SamWorthington"`), so `CountVectorizer` treats them as a single token instead of splitting on the space and diluting the signal with common first/last names shared across many people.
- **Poster fetching lives in `app.py`, not `recommendation.py`.** `recommend()` returns movie rows (title, `movie_id`); fetching a poster image is a display concern, not a recommendation concern, and keeping it in the app layer means `recommendation.py` has no network dependency and can be tested in isolation.
- **A failed poster fetch falls back to a placeholder image rather than raising.** TMDB requests can time out, rate-limit, or return a movie with no `poster_path` on file; none of these are actual bugs in the recommender, so they shouldn't crash the app.

## Known Limitations

- **Recommendations are looked up by exact title match.** Two movies sharing the same title (this dataset has more than one movie titled "Batman") resolve to whichever row appears first — there's no `movie_id`-based disambiguation in the UI.
- **No caching on poster fetches.** Every "Show Recommendation" click re-fetches all 5 posters from TMDB, even for a repeated selection.
- **The dataset is static.** Adding a new movie means manually appending to the source CSVs and re-running `train.py`; there's no ingestion pipeline for new titles.

## Possible Next Steps

- Cache poster fetches (`st.cache_data`) to cut redundant TMDB calls
- Cache the loaded model artifacts (`st.cache_resource`) instead of reloading pickles on every rerun
- Add a slider to control the number of recommendations returned (currently fixed at 5)
- Add a "Surprise me" button that recommends from a random movie
- Disambiguate duplicate titles by showing release year or `movie_id` alongside the title
